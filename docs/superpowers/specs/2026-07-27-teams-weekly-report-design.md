# 既卒生 メモリア週次レポート → Teams 自動送信 設計

作成日: 2026-07-27

## 目的

2026年度既卒生（国家試験対策対象者24名）のメモリア実施状況を、毎週月曜の朝に
担当教員（藤吉先生）の Teams チャットへ自動で届ける。教員が「今週誰に声をかけるか」を
1通のメッセージで判断できる状態にする。

## 前提と制約（調査で確定した事実）

- 対象者は `/Users/ny/Documents/2026既卒生国家試験対策進捗状況一覧20260604.xlsx` の24名。
  同ファイルは 2026-06-04 時点のスナップショットであり、氏名と分類（①〜⑥）しか持たない。
  学籍番号を持たないため、**このファイル自体をシステムのデータソースにはしない**。
- 学生名簿スプレッドシート（ScriptProperty `STUDENT_LIST_ID`）の `students` シートに
  `student_number` / `student_name` / `department` / `grade` があり、24名は登録済み。
  ただし `grade=4` だけでは他の学生と区別できず（入学年違いの既卒生も混在）、
  **「今回の対象24名」を示す情報が存在しない**。
- **大半の対象者はまだメモリアを実施しておらず、`student_logs` に1行も存在しない。**
  したがって「誰が未着手か」はログから導出できない。対象者名簿を明示的に持つことが必須。
- 学習ログは `student_logs` に蓄積され、`ArchiveService` が古い分を
  `student_logs_YYYY-MM` シートへ退避する。累計値の算出はアーカイブも走査する必要がある。
- 既存の `automation/parent-report/ParentReport.gs` が、既卒生の月次集計 →
  Gemini 文面生成 → Power Automate 送信という近い処理を実装済み。集計部分の考え方を踏襲する。

## 決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| 送信経路 | Power Automate（HTTP要求トリガー）→ チャットに投稿 | 個人チャットへのDMが可能。保護者レポートと運用系統が揃う |
| 送信タイミング | 毎週月曜 7:00 JST（先週月〜日を集計） | 週の頭にその週のフォロー対象が確定する |
| 未着手者の表示 | 全員の氏名を列挙（経過週数つき） | 24名なら1通で全体像が読める。放置が長い順に声をかけられる |
| 分類①〜⑥・月次目標 | **レポートには使わない** | 教員の手元管理に留める。仕様変動をシステムに持ち込まない |
| AI 文面生成 | **行わない** | 事実の集計のみ。追加課金ゼロ、氏名を外部APIに送らない |

## アーキテクチャ

```
[students シート]           [student_logs / student_logs_YYYY-MM]
  report_group='2026既卒'            回答ログ
        │                                │
        └────────┬───────────────────────┘
                 ▼
   TeamsWeeklyReport.gs（週次トリガー 月 7:00）
                 ├─ 集計・状態判定
                 ├─→ 週次Teams_YYYYMMDD シート（記録・検証用）
                 └─→ POST JSON → Power Automate → Teams チャット（藤吉先生）
```

### 構成要素

**1. 対象者定義 — `students` シートの `report_group` 列（新規追加）**

対象24名の行に `2026既卒` と入力する。対象の増減はこの列の編集のみで完結し、
コード変更を伴わない。値は文字列で、将来 `2027既卒` などを並行運用できる。

- 責務: 「誰にレポートするか」の唯一の正本
- インターフェース: `student_number` をキーに `student_name` と `report_group` を返す
- 依存: なし（教員が手で編集する）

**2. 集計・送信 GAS — `automation/teams-weekly/TeamsWeeklyReport.gs`**

問題バンクスプレッドシートの Apps Script プロジェクトに配置する。

- 責務: 週次の集計、シートへの記録、Power Automate への送信
- 主要関数:
  - `buildAndSendWeeklyReport()` — トリガーから呼ばれる本体
  - `buildWeeklyReport(dryRun)` — 集計してシート出力まで。`dryRun=true` なら送信しない
  - `collectWeeklyStats_(ss, from, to)` — 対象者ごとの集計（下記データ構造を返す）
  - `formatMessage_(stats, from, to)` — 送信ペイロードの組み立て
  - `postToTeams_(payload)` — UrlFetchApp による POST とエラー処理
  - `installWeeklyTrigger()` — 初回に一度だけ手動実行
- 依存: `students` シート、`student_logs`（＋アーカイブ）、ScriptProperties

**3. 送信先 — Power Automate フロー**

「HTTP 要求の受信時」トリガー → 「チャットまたはチャネルにメッセージを投稿」
（投稿者: フロー ボット、投稿先: 藤吉先生とのチャット）。
フロー URL は ScriptProperty `TEAMS_FLOW_URL` に保存し、**リポジトリには置かない**。
URL 自体が共有秘密であり、CLAUDE.md の secret 判定基準に該当する。

## データフロー

1. トリガー起動（月曜 7:00）
2. `students` から `report_group='2026既卒'` の行を取得 → 対象 `student_number` 集合
3. `student_logs` および `student_logs_*` アーカイブシートを走査し、対象者の
   ログのみを抽出（対象外の学生は読み飛ばす）
4. 学生ごとに集計:
   - 今週（月00:00〜日23:59:59 JST）の回答数・学習日数・正答率
   - 累計回答数・最終学習日・初回学習日
5. 状態を4分類に判定:

   | 状態 | 条件 |
   |---|---|
   | 今週実施 | 今週の回答数 ≥ 1 |
   | 今週はじめて着手 | 今週実施 かつ 初回学習日が今週内 |
   | 停止中 | 今週の回答数 = 0 かつ 累計 ≥ 1 かつ 最終学習日から14日以上経過 |
   | 未着手 | 累計回答数 = 0 |

   （今週未実施だが最終学習日から14日未満の学生は「今週実施」にも「停止中」にも
   該当しないため、`小休止（N日前に学習）` として停止中セクションの下に短く出す）

6. `週次Teams_YYYYMMDD` シートへ全対象者の集計結果を書き出す
7. 送信済みフラグを確認し、未送信ならペイロードを POST
8. POST 成功 → 送信済みフラグを立てる／失敗 → `ADMIN_EMAIL` へエラーメール

### 未着手者の経過週数

「登録からどれだけ未着手か」の起点は次の順で決める:

1. `enrolled_students` シートに当該 `student_number` の `created_at` があればその日付
2. なければ ScriptProperty `PROGRAM_START_DATE`（既定値 `2026-05-01`＝事前アンケート開始月）

未着手者はこの経過週数の降順（放置が長い順）で並べる。

## メッセージ形式

```
📊 メモリア週次レポート  7/20(月)〜7/26(日)
対象 24名 ／ 今週実施 3名 ／ 累計未着手 19名

✅ 今週実施（3名）
  山田 太郎   42問・4日・正答率58%
  佐藤 花子     18問・2日・正答率44%
  鈴木 一郎    7問・1日  🌱今週はじめて着手

😴 停止中（14日以上・2名）
  田中 二郎   最終 7/2（24日前）・累計112問
  高橋 三郎   最終 6/28（28日前）・累計 35問

⛔ 未着手（19名／未着手期間の長い順）
  伊藤 四郎（12週）  渡辺 五郎（12週）  小林 六郎（11週）…

▶ 詳細シート: <スプレッドシートURL>
```

「小休止」該当者がいる週は、停止中セクションの直後に
`💤 小休止（1名）  加藤 七海  最終 7/24（3日前）` の形式で1行ずつ足す。

該当者ゼロのセクションは見出しごと省略する。全員未着手の週も
「今週実施 0名」を明示して送信する（送らないと故障と区別できないため）。

## エラー処理

| 事象 | 挙動 |
|---|---|
| `TEAMS_FLOW_URL` 未設定 | シート出力のみ行い、`ADMIN_EMAIL` へ「未設定のため未送信」を通知 |
| POST が非2xx／例外 | 最大3回リトライ（指数バックオフ）。全滅で `ADMIN_EMAIL` へエラーメール。シートは残る |
| `report_group` 該当者ゼロ | 送信せず、管理者へ「対象者未設定」を通知（無言で成功扱いにしない） |
| 同一週の再実行 | 送信済みフラグにより二重送信しない。シートは上書き更新 |
| `students` シート／列が見つからない | 例外を投げて停止し、管理者へ通知 |

## テスト方針

GAS のためユニットテスト基盤がない。以下の手順で検証する。

1. `buildWeeklyReport(true)`（dryRun）を実行 → `週次Teams_YYYYMMDD` シートの内容を
   スプレッドシート上の実データと突き合わせて手検証する
2. 状態判定は、ログを持つ学生・持たない学生・14日以上前に止まった学生が
   それぞれ意図した区分に入ることを実データで確認する
3. `TEAMS_FLOW_URL` を設定し単発送信 → Teams チャットでの表示崩れを確認
4. 二重送信ガードの確認（同じ週にもう一度実行しても届かないこと）
5. `installWeeklyTrigger()` を実行し、翌週の自動配信を実地で確認する

いずれも「実行して結果を目視した」時点で検証済みとし、それ以前に動作を断定しない。

## 導入手順（運用者の作業）

1. `students` シートに `report_group` 列を追加し、対象24名に `2026既卒` を入力
   （xlsx の氏名と `students` の突き合わせ候補一覧は実装時に生成する）
2. Power Automate でフローを作成（手順書を実装時に同梱）
3. Apps Script に `TeamsWeeklyReport.gs` を貼り付け、ScriptProperties に
   `TEAMS_FLOW_URL` / `ADMIN_EMAIL` を設定
4. `buildWeeklyReport(true)` で dryRun → 内容確認
5. `installWeeklyTrigger()` を実行

## スコープ外（YAGNI）

- 分類①〜⑥および月次目標の達成判定
- 正答率・苦手分野の詳細分析（実施者が増えた段階で別途追加する）
- AI による文面生成
- 学生本人への通知、教員からの返信受付
- 他学科・在校生への展開

## 将来の拡張ポイント

実施者が一定数を超えたら、`formatMessage_` に苦手分野セクションを追加する。
集計には `ParentReport.gs` の `collectMonthlyStats_` / `loadCategoryMap_` と
同じカテゴリ集計ロジックを流用し、二重メンテを避ける。
