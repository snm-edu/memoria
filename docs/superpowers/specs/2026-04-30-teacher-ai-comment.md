# 教員向け AI コメント (Phase D-2a) — 設計と運用メモ

**初版**: 2026-04-30 (オンデマンド方式)
**改訂**: 2026-04-30 (日次バッチ方式へ転換 + 出題比重ベースの具体化)
**スコープ**: 個別学生×教員視点の AI コメント。クラス全体サマリは対象外。

## 設計方針: 日次バッチ + ダッシュボード即時表示

### 採用した方式

毎朝 4 時の `runDashboardUpdate` トリガーで全学生の `teacher_comment` を一括生成し、Looker 教員ダッシュボードがスプレッドシート参照で即時表示する。

### 方式選定の経緯

| 検討した方式 | 採用結果 | 理由 |
|----------|--------|------|
| 日次バッチ (初版検討) | ✗ → ✓ 採用 | コスト懸念で一旦オンデマンドへ。後に Looker 制約で再採用 |
| オンデマンド (中間案) | ✗ 撤回 | クリック時に新タブが開く挙動を回避できないと判明 |
| 日次バッチ + オンデマンド併用 | ✗ | 維持コストとUI複雑性のため不採用 |
| 日次バッチ単独 | ✓ 採用 | Looker 内完結、教員操作不要、コストも許容範囲 |

### Looker Studio の構造的制約 (オンデマンド断念の根拠)

- 任意 JavaScript 実行不可
- AJAX/Fetch 呼び出し不可
- リンククリック = 必ずタブ遷移 (新タブ or 現タブ離脱)

「クリック → ダッシュボード内で完了」は標準機能では物理的に不可能。

### コスト試算 (採用方式)

| 項目 | 数値 |
|------|------|
| 学生数 | 600 名 (4 学科 × 150 名平均) |
| 1 学生あたり Gemini 呼出 | 学生向け 1 + 教員向け 1 = 2 回/日 |
| 月次総呼出 | 600 × 2 × 30 = 36,000 回 |
| 単価 (`gemini-2.5-flash-lite` Paid) | $0.0002〜$0.0003/回 |
| 月次コスト | 約 $7〜$10 |
| CLAUDE.md 上限 | $10 (spending cap) |

差分最適化 (`dataUnchanged` && `existing.teacherComment` で再利用) により、平日学習しない学生分は再生成スキップ。実コストは $5 前後を想定。

## 出題比重ベースの優先度ランキング

教員向けプロンプトは抽象的にならないよう、**カテゴリ別の優先度ランキング**を計算してプロンプトに渡す。

### スコア計算式

```
priorityScore = examWeightPct × gapFactor

  examWeightPct = (該当カテゴリのマスタ問題数 / 学科マスタ全問題数) × 100
  gapFactor     = 未着手なら 1.0, 着手済なら (100 - currentRate) / 100
```

### 出力例 (臨床工学技士学科 / 1年生)

```
【優先1位】「医用電気電子工学」 / 出題比重 65% (2,340 問) / 正答率 21% (130 問着手)
【優先2位】「医学概論」 / 出題比重 12% (430 問) / 未着手
【優先3位】「医用機器安全管理学」 / 出題比重 8% (290 問) / 正答率 35% (60 問着手)
...
```

このランキング上位 5 件 + 全カテゴリ名リストを「許可カテゴリ名リスト」としてプロンプトに渡す。AI は許可リスト外の名称を本文で使用禁止。

## プロンプト構造 (`generateTeacherComment`)

### 絶対禁止事項

- データに無いカテゴリ名・試験区分・分野名の創作
- 出題形式の区分名 (必修問題 / 状況設定問題 / 一般問題 / 状況問題)
- 国家試験名の本文掲載
- 抽象表現 (「基礎の確認」「基本事項の演習」)

### 文体ルール

- 教員視点 (「この学生は」「本生徒は」)
- 学生への呼びかけ語禁止 (あなた / 皆さん / きみ)
- 学生氏名禁止 (Looker フィルタで識別済)
- 学年番号禁止 (上下学年混在のため)

### 出力構成 (3点必須)

1. **観察**: 全体正答率 + 優先度1位カテゴリ名 + 出題比重 + 現状を1文
2. **着手提案**: 「『〇〇』は出題比重〇%を占め現在〇〇のため、ここから着手」 形式
3. **次の一手**: 個別面談 / 補講 / 授業計画 のいずれか1つに絞り、許可カテゴリ名を引用した具体行動

### 出力例 (実運用)

```
本生徒は全体正答率11%と低調であり、優先度1位の「医用電気電子工学」は
出題比重65%を占めるものの、正答率21%で未着手率も高い。
「医用電気電子工学」は出題比重65%を占め現在正答率21%のため、ここから着手する。
個別面談において、学習習慣の確立と「医用電気電子工学」の基礎事項に
焦点を当てた個別指導を計画する。
```

## 実装構造

### 主要メソッド (`DashboardService.gs`)

| メソッド | 役割 |
|---------|------|
| `updateAll` | 日次バッチ本体。loop 内で学生向け+教員向けの両 AI を生成 |
| `buildUnstudiedStats` | 未着手率計算 (curriculum 累積範囲ベース) |

### 残置ファイル (将来用)

オンデマンド方式を一時的に試した際の残骸として以下が残る (運用上は害なし):

- `gas-backend/src/TeacherCommentService.gs` — オンデマンド HTML エンドポイント実装

将来 (例: 緊急の手動再生成が必要になった場合) に再利用可能。完全削除する場合は両方同時に。

## Looker Studio ダッシュボード構成

### ページ構造 (5 ページ)

1. 全体 (4 学科サマリ)
2. 看護学科 (`department = 'nursing'` フィルタ)
3. 視能訓練士学科 (`department = 'orthoptist'`)
4. 歯科衛生士学科 (`department = 'dental_hyg'`)
5. 臨床工学技士学科 (`department = 'clinical_eng'`)

各学科ページは臨床工学ページの複製でフィルタのみ差し替え。

### AIアドバイス表 (各学科ページ)

- ディメンション: `teacher_comment` のみ
- 指標: `学生ID` (カウント、列幅最小化で実質非表示)
- フィルタ: 上部の氏名プルダウンと連動

### 分野別学習マップ (treemap)

- 計算フィールド `progress_bucket` で 11 段階の RdYlGn グラデーション
  - `00_未着手` (#CBD5E1) → `01` (#A50026) → ... → `10` (#006837)
- ディメンション色設定でバケット別に固定
- データに無いバケットは凡例から自動省略 (Looker 仕様)

## 運用・確認手順

### 日次運用 (自動)

1. 04:00 — `runDashboardUpdate` トリガー発火
2. 600 名分のループ (差分なしはスキップ)
3. ai_dashboard シート全行更新
4. category_stats シート更新 (treemap 用)
5. ログ出力: `教員AI: 生成 X名 / 再利用 Y名`

### 手動運用 (緊急再生成)

学生コメントが特定カテゴリで創作された等の理由で再生成したい場合:

1. ai_dashboard シート P 列 (P2 以降) の該当範囲をクリア
2. GAS エディタで `runDashboardUpdate` を手動実行 (30 分上限)
3. ログで結果確認

### 動作確認

| 項目 | 確認場所 | 期待値 |
|------|--------|------|
| teacher_comment の存在 | ai_dashboard シート P 列 | 全行に文字列、updated_at 04:xx |
| 4学科カテゴリ正確性 | Looker AI アドバイス表 | 各学科のカテゴリ名のみ、創作なし |
| 出題比重引用 | Looker AI アドバイス表 | 「出題比重〇%」が本文に含まれる |
| プロンプトバイアス確認 | 4 学科それぞれ複数学生でテスト | 必修問題等の創作語が出ない |

## セキュリティ要件

教員コメントは個人情報に近い (面談指針) ため、PWA レスポンスには含めない。

| 経路 | teacher_comment 取扱 |
|------|------------------|
| `getDashboard` (PWA → API) | レスポンス JSON から除外 |
| `refreshDashboard` (PWA → API) | 既存値を保持、API レスポンスから除外 |
| Looker Studio (教員ダッシュボード) | スプレッドシート直接参照で表示 |
| 教員ダッシュボードへのアクセス制御 | Google アカウント単位の Looker 共有設定で管理 |

## 既知の制約と将来の拡張余地

1. **Gemini 単価変動**: 価格改定で月次コストが上振れる可能性あり。spending cap $10 で防御
2. **GAS 実行時間**: 600 名一斉再生成は 30 分上限に近い。将来 1,200 名に増えると分割実行が必要
3. **凡例の不完全表示**: ある学生に該当バケット (例: 03) のデータが無いと凡例から消える。Looker 仕様
4. **教員コメントの説明性**: 現状はテキスト出力のみ。将来的に「優先度ランキング表」をダッシュボードに併記すると教員の判断材料が増える
5. **学年帯の扱い**: 同じ学生が下級学年問題を解くケースのため、本文で学年を断定しない。プロンプトで明示禁止済
